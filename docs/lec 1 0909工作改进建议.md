### B1 换行符未过滤（🟠 中）

`_clean_name()` 里的 `value.strip()` 只去掉**首尾**空白，名字**内部**的 `\n` 会原样进入输出；`escape()` 只管 Rich 标记，不管换行。

```text
$ python main.py hello --name $'evil\nAI Coding Agent CLI v9.9'

AI Coding Agent CLI v0.1
Hello, evil
AI Coding Agent CLI v9.9! Welcome to AI Coding Agent CLI.   # ← 伪造出来的"横幅"
```

后果：脚本/CI 若按行解析输出（例如 `tail -1`、grep 关键字），会被伪造行欺骗；在日志系统中也表现为凭空多出一行。

### B2 ANSI 转义序列未过滤（🟠 中）

```text
$ python main.py hello --name $'\x1b[31mRED\x1b[0m' | cat -v

AI Coding Agent CLI v0.1
Hello, ^[[31mRED^[[0m! Welcome to AI Coding Agent CLI.   # ← 真实 ESC 字节被写进输出流
```

`^[[31m` 是 `cat -v` 对真实 `ESC`（0x1B）的显示形式，说明 ESC 字节**确实被透传**。用户可借此在本终端里改色、移动光标，甚至构造"假提示符"。

补充：Rich 并不帮我们兜底。`.venv/.../rich/control.py` 中：

```python
STRIP_CONTROL_CODES: Final = [7, 8, 11, 12, 13]   # bell/backspace/VT/FF/CR，不含 27(ESC)
```

即 Rich 只清理 8 个控制码中的 5 个，**ESC(27)、`\n`(10)、`\t`(9) 都不在列**；内置 `print()` 同样原样输出。

### B3 超长名字软换行（🟡 低）

```text
$ python main.py hello --name $(python3 -c 'print("A"*120)')

AI Coding Agent CLI v0.1
Hello,
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA! Welcome to AI Coding Agent CLI.
```

4 行输出（默认 `Console(width=80)` 软换行），与"横幅 + 欢迎语两行"的约定不符，也让基于行号的断言失效。

### B4 自动高亮导致同一输入渲染不一致（🟡 低）

Rich 默认 `highlight=True`，会对数字/路径/URL 自动上色。用 `force_terminal=True` 实测：

```text
Hello, <紫>/tmp/</紫><亮紫>data.csv</亮紫>! Welcome to AI Coding Agent CLI.
Hello, <下划线亮蓝>https://x.dev!</下划线亮蓝> Welcome to AI Coding Agent CLI.
Hello, <加粗青>42</加粗青>! Welcome to AI Coding Agent CLI.
```

所以 `--name 42`、`--name /tmp/x.csv` 的颜色与 `--name abc` 不同。纯装饰性问题，但截图/录屏做教程时会出现"同样的命令颜色不一样"，容易被误认为程序有状态。

### B5 已修复项回归（✅）

上一轮用 `escape(name)` + `_clean_name()` callback 修的两个问题已回归验证：

## 二、代码风险

### R1 版本号三处漂移（🟠 中）
`VERSION = "0.1"` 目前只存在于 [main.py:11](./main.py#L11)，但 `requirements.txt`、将来的 `pyproject.toml`、README 都会各写一份。三人四处手改必然不同步，且**没有任何自动化机制能发现不一致**。

### R2 缺少 `--version` 选项（🟡 低）
实测 `python main.py --version` → `No such option: --version`，退出码 2。主流 CLI 惯例是顶层选项（`git --version`、`ruff --version`），当前只有 `version` 子命令，用户首次尝试大概率踩空。

### R3 没有打包入口（🟠 中）
项目无 `pyproject.toml`，无法 `pip install -e .`，也就没有 `ai-agent hello` 这样的全局命令。随着 `app/cli`、`app/core`、`app/llm`、`app/tools` 陆续有实现，`from app.llm import ...` 这类导入会因"当前工作目录决定 `sys.path`"而时对时错（换个目录执行就 `ModuleNotFoundError`）。

### R4 零测试保护（🟠 中）
`tests/` 目录为空，`.venv` 内无 `pytest`。当前项目唯一的"契约"就是那两行输出文字，而它**没有任何测试锁定**：后续把命令下沉到 `app/cli/` 时，任何一处 f-string 改动都不会报错，只会在下次人肉运行时才发现。

### R5 模块级全局 `console`（🟡 低）
[main.py:17](./main.py#L17) 在导入时就创建 `Console()` 单例。好消息是 Rich 的 `Console.file` 是**惰性求值**（源码：`file = self._file or (sys.stderr if self.stderr else sys.stdout)`），因此测试里重定向 `sys.stdout` 仍能捕获输出（已实测 `captured: 'AI Coding Agent CLI v0.1\n'`）。风险在于：想换宽度、导出 HTML、单独捕获横幅时无法注入，函数签名里没有"依赖入口"。

### R6 stdout / stderr 分流需知晓（🟡 低）
实测：`--help` → **stdout**；`python main.py`（裸命令，`Missing command`）→ **stderr** 且退出码 2。写测试或 shell 断言时如果混用 `2>&1`，很容易把"用法错误"当成"正常输出"。

### R7 常量未做标记转义（⚪ 极低）
`APP_NAME` 直接写进 `[bold cyan]...[/bold cyan]`（[main.py:22](./main.py#L22)）。当前值是开发者自控的安全字符串，但若将来改成读取配置文件（如 `pyproject.toml` 里的项目名），就会引入与 B5 同源的崩溃路径。

### R8 终端能力差异（⚪ 极低）
Rich 在非 TTY（管道、CI、重定向）下自动降级为纯文本，本机验证输出干净；但依赖环境的 `TERM`/`NO_COLOR`。若在 CI 里断言颜色，会因环境不同而 flaky。

## 三、改进建议

### A. 立即可做（改动小、已验证有效）

**A1 强化 `_clean_name()`** —— 折叠空白 + 过滤控制字符，一并解决 B1、B2

```python
import re

_CONTROL_RE = re.compile(r"[\x00-\x1f\x7f]")   # C0 控制符 + DEL（含 ESC、\n、\t）
MAX_NAME_LEN = 40


def _clean_name(value: str) -> str:
    """规范化名字：折叠空白、去掉控制字符、限制长度。"""
    name = " ".join(value.split())        # \n、\t、连续空格 → 单个空格
    name = _CONTROL_RE.sub("", name)      # 去掉不可见控制字符（含 ANSI 的 ESC）
    if not name:
        raise typer.BadParameter("名字不能为空")
    if len(name) > MAX_NAME_LEN:
        raise typer.BadParameter(f"名字过长（最多 {MAX_NAME_LEN} 个字符）")
    return name
```

**A2 关闭自动高亮** —— 解决 B4

```python
console.print(f"Hello, {escape(name)}! Welcome to {APP_NAME}.", highlight=False)
```

**A1 + A2 组合后的实测结果**（`force_terminal=True, width=100`，`<ESC>` 标记真实转义字节）：

| 输入 | 输出 | 判定 |
|---|---|---|
| `张三` | `Hello, 张三! Welcome to AI Coding Agent CLI.` | ✅ 中文正常 |
| `'  Li Ming  '` | `Hello, Li Ming! ...` | ✅ 首尾空白已修剪 |
| `$'a\tb'` | `Hello, a b! ...` | ✅ 制表符折叠为空格 |
| `$'evil\nFAKE'` | `Hello, evil FAKE! ...` | ✅ 换行被消除，无法伪造行 |
| `$'\x1b[31mRED\x1b[0m'` | `Hello, [31mRED[0m! ...` | ✅ 无真实 ESC 字节，退化为可见文本 |
| `'[/bold]'` / `'[bold]x'` | 原样显示 | ✅ 标记注入仍被 `escape()` 兜住 |
| `42` / `/tmp/x.csv` / URL | 全为纯文本、无颜色 | ✅ 高亮已关闭 |
| 120 个 `A` | 报错"名字过长"退出码 2 | ✅ 不再撑破两行契约 |

> 注：若不想"报错"而想"截断"，把长度分支改为 `name = name[:MAX_NAME_LEN]` 即可，但截断可能切断 emoji 组合序列，需额外处理，当前阶段建议先用报错。

### B. 结构性改进

**B1 增加 `--version` 顶层选项**（解决 R2）

```python
@app.callback()
def _root(
    show_version: bool = typer.Option(
        False, "--version", "-V", help="显示版本号并退出", is_eager=True
    ),
) -> None:
    if show_version:
        console.print(f"{APP_NAME} v{VERSION}")
        raise typer.Exit()
```

`is_eager=True` 让它在子命令解析前就生效，因此 `python main.py hello --version` 也能直接输出版本。注意回调函数**不要加下划线以外的名字**冲突：Typer 会把顶层 callback 当作"根命令"处理。（另：Typer 还支持把子命令改名或直接删掉 `version` 子命令，二者可并存，无冲突。）

**B2 版本号单一来源**（解决 R1）

```python
from importlib.metadata import version          # 从包元数据读取，pyproject 里改完即生效
VERSION = version("ai-coding-agent-cli")
```

过渡期若尚未打包，则保留常量，但务必在 `pyproject.toml` 里用 `dynamic = ["version"]` + `[tool.hatch.version] path = "main.py"` 之类的机制绑定，避免手改两处。

**B3 打包与入口点**（解决 R3）

```toml
# pyproject.toml（新增）
[project]
name = "ai-coding-agent-cli"
version = "0.1"

```

之后 `pip install -e ".[dev]"`，就能用 `ai-agent hello --name 张三` 替代 `python main.py ...`，同时消除"必须在项目根目录执行"这一隐性约束（R3 的后半段）。

**B4 命令实现下沉到 `app/cli/`**（为后续 Task 腾位置）

`main.py` 只留装配与入口，`app/cli/commands.py` 放 `hello`/`version`，`app/cli/__init__.py` 导出 `app`。好处：`main.py` 保持 10 行以内，`app/tools`、`app/llm` 的实现可以正常 `from app.core import ...`，也让测试的 import 路径稳定。

### C. 工程化改进

**C1 补测试（解决 R4）** —— `pytest` + Typer 官方 `CliRunner`，把两行输出锁死

```python
# tests/test_cli.py
import pytest
from typer.testing import CliRunner
from main import app

runner = CliRunner()


def test_hello_default():
    result = runner.invoke(app, ["hello"])
    assert result.exit_code == 0
    assert "Hello, Developer! Welcome to AI Coding Agent CLI." in result.output


def test_hello_with_name():
    result = runner.invoke(app, ["hello", "--name", "张三"])
    assert result.exit_code == 0
    assert "Hello, 张三! Welcome to AI Coding Agent CLI." in result.output


@pytest.mark.parametrize(
    "bad_name",
    ["", "   ", "[/bold]", "evil\nFAKE", "\x1b[31mRED"],
)
def test_hello_rejects_or_neutralizes_bad_name(bad_name):
    result = runner.invoke(app, ["hello", "--name", bad_name])
    if bad_name.strip() == "":
        assert result.exit_code == 2
    else:
        assert result.exit_code == 0
        assert "\x1b" not in result.output      # 不得出现真实转义字节
        assert result.output.count("\n") == 2   # 严格两行
```

注意断言用 `in result.output` 而非 `==`：Typer 的 `CliRunner` 会合并 stdout/stderr，且对 `--help` 等路径会附加用法行。
